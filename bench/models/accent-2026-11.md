# Which free CPU model should Silas use by default (2026-11)

Studied 2026-11-18 on chapel1 (Intel Core i5-10210U, 4 cores, 3 of them used, no GPU). Numbers:
[accent-2026-11.json](accent-2026-11.json), made from [accent-2026-11.candidates.json](accent-2026-11.candidates.json)
and the per-clip rows (gzipped) in `accent-2026-11/` by `summarize.py`.

## Verdict

**Make Parakeet TDT 0.6B v3, Q4_K_M GGUF, run through transcribe.cpp (the `transcribe-cpp` crate), Silas's default.**
It is the same model Silas ships, run by a different engine: accent WER falls from 26.0% to 12.0%, overall WER from
6.5% to 4.4%, formatted error from 15.2% to 13.6%, with the same wait after key up (1063 ms median against 1090,
and 875 against 1009 in a real-time run), 300 MB less peak memory (1064 MB against 1366), a model load of 0.23 s
instead of 1.3 s, and a download of about the same size (485 MB against 478). It keeps all 25 languages.

Silas's accent gap was never the model. Hex's model, Parakeet Unified, beats Silas on accents (18.0%), but Parakeet
v3 on transcribe.cpp beats both (11.8 to 12.0%). The gap is Silas's engine, transcribe-rs over ONNX, in two parts:

1. **Its TDT decoder ignores the duration head.** Parakeet TDT predicts a token and how many frames to skip;
   transcribe-rs 0.3.12 keeps only the token and steps one frame at a time, so on a stutter it emits the same
   word again and again. Honoring the duration (a 15-line fix, [transcribe-rs-tdt-durations.patch](transcribe-rs-tdt-durations.patch))
   takes accent WER from 26.0% to 19.8%.
2. **The int8 ONNX encoder loses accuracy.** With the decoder fixed, the full-precision encoder reaches 12.8%,
   level with GGUF Q8_0 (11.8% on the same clips), while the int8 encoder with a full-precision decoder stays at
   19.8%. Matching transcribe.cpp on ONNX would take the 2.4 GB fp32 encoder and 2.7 GB of memory.

Tradeoffs of the switch, named:

- **Build.** transcribe-cpp compiles transcribe.cpp and ggml from vendored source with CMake and links them
  statically. Silas's CI and release builds need CMake and a C++ compiler on macOS, Windows and Linux, and a clean
  build takes longer (not timed here). onnxruntime stays only if Cohere stays on ONNX; transcribe.cpp has a Cohere
  architecture and `handy-computer/cohere-transcribe-03-2026-gguf` exists, though that build was not scored here.
- **Code clips.** v3 on GGUF gets 20.7% on code against 19.8% on ONNX. Cohere 2B is the best at code (13.8%) but
  waits 4.5 s after key up on this CPU.
- **New downloads.** The GGUF comes from `handy-computer/parakeet-tdt-0.6b-v3-gguf` on Hugging Face; Silas would
  mirror it in its own release like the ONNX tarball today.
- **Q4_K_M or Q8_0.** They tie (accent 12.0 against 11.8, overall 4.4 against 4.3, every confidence interval
  overlapping, the same punctuation F1). Q4_K_M is 255 MB smaller on disk and 240 MB smaller in memory. Pick Q8_0
  only if a later, larger set separates them.
- **If Silas stays on ONNX for now,** ship the decoder fix anyway: it is free (same files, same speed, a little
  faster) and closes about 40% of the accent gap. Upstream it to transcribe-rs; until a release has it, carry it as
  a `[patch.crates-io]`.

Close calls not taken:

- **Parakeet Ultra Q8_0** (Moondream's post-trained v3) ties v3 on accent (11.8%) and overall (4.3%) with slightly
  better punctuation, but it loses on dictation clips (8.3% against 6.9%) and has no measured Q4 build here.
- **Parakeet Unified English** (Hex's default) wins clean, noise, dictation and longform by a little (each within
  the intervals) but loses accent (18.0%), code (23.5%) and punctuation (F1 0.656 against 0.754), and it is English
  only.
- **Qwen3-ASR 0.6B** gets 15.2% on accent, but waits 2.2 s after key up and spends 47 CPU seconds per audio minute.
- **Moonshine Base** is the lightest by far (77 MB, 288 MB peak, 520 ms wait, 8.6 CPU s per audio minute) and
  good on dictation (5.5%), but it misses 26.7% of accented words and 11.3% of command words. It is worth keeping
  in mind as a low-end fallback, not a default.

Model load with the files already in the page cache, 3 cores, two runs each: Parakeet v3 int8 ONNX 1.32 to 1.37 s; v3 Q4_K_M GGUF 0.22 to
0.24 s; v3 Q8_0 GGUF 0.23 s; Unified Q8_0 0.21 s; Moonshine Base 0.03 to 0.04 s.

### Fillers left out

`score.py` keeps "uh" and "um" in the reference, so a model that drops them loses words the app would remove
before typing anyway. With fillers dropped from both sides (`wer_without_fillers` in the JSON), accent WER is 22.3
(Silas today), 19.1 (decoder fix), 15.6 (Unified Q8_0), 11.5 (v3 Q4_K_M), 11.2 (v3 Q8_0), 10.7 (Ultra), 13.2
(Qwen3), 16.3 (Canary), 17.3 (Cohere), 19.8 (Moonshine Streaming Medium), 24.7 (Moonshine Base). The top of
the order does not change; two pairs lower down swap (Cohere passes the decoder fix, and Silas today passes
Granite at 22.9).

## Why Silas loses on accents

Same weights, two engines: on the 50 accent clips, Silas's ONNX run made more errors than the v3 Q8_0 GGUF on 32
clips and fewer on 4. The worst ONNX clips are loops on a stutter or a filler:

| Clip | Reference (verbatim) | Word | In the reference | In Silas's text |
| --- | --- | --- | ---: | ---: |
| accent-0041 | "successful at at at this diet and uh you can uh uh uh prepare for yourself" | at, uh | 3, 4 | 21, 33 |
| accent-0044 | "oh so so so for me to me i if i eat like less meat ..." | so | 3 | 31 |
| accent-0005 | "i i i i could really say that i influenced you into watching more of animation" | i | 5 | 15 |

Parakeet TDT's joint network scores the vocabulary (8,193 tokens with blank) and five durations (0 to 4 frames).
NeMo's greedy decoder emits the best token and advances by the best duration. transcribe-rs 0.3.12
(`src/onnx/parakeet/mod.rs`, `decode_sequence`, unchanged on its main branch) reads only the vocabulary and advances
one frame after a blank or after 10 tokens, so a frame that looks like "so" yields "so" up to 10 times, and the
next frame does it again. The patch takes the duration argmax and advances by it.

Diagnostics on the 50 accent clips (rows in `accent-2026-11-fp32/`, scored by the same script):

The fix alone helps most; the int8 encoder costs the rest. transcribe.cpp's K-quants keep the encoder's accuracy
at a third of the fp32 size.

## Wait after key up in real time

`--fast` simulates the waiting from real model time. To check it, the 40 ratchet clips (`bench/subsets/ratchet.txt`)
ran again in real time, no `--fast`, same cores (rows in `accent-2026-11-paced/`):

| Model | Run | WER | Accent WER | Wait p50 ms | Wait p95 ms |
| --- | --- | ---: | ---: | ---: | ---: |
| Parakeet v3 int8 ONNX (Silas today) | real time | 7.8 | 28.7 | 1009 | 1367 |
| | `--fast` | 8.2 | 29.5 | 878 | 1170 |
| Parakeet v3 Q4_K_M GGUF | real time | 5.3 | 10.7 | 875 | 1150 |
| | `--fast` | 5.2 | 10.7 | 872 | 1166 |
| Parakeet v3 Q8_0 GGUF | real time | 5.4 | 9.8 | 845 | 1163 |
| | `--fast` | 4.9 | 9.8 | 857 | 1180 |

Silas's real-time accent WER here is 28.7%, the number PR #39 recorded on these clips, and Hex scored 14.8% there.
The GGUF models wait the same in real time as `--fast` says. Silas's ONNX engine waits about 130 ms longer in real
time than `--fast` shows (not diagnosed here; onnxruntime's spinning thread pool on 3 shared cores is a likely
cause), so the full-set
table, if anything, flatters today's engine. As HARNESS.md notes, a few clips come out a word different between
the two runs (4 to 6 of 40 here).

## Method

- Every model goes through Silas's dictation path (`core/voice/src/replay.rs`): pieces cut at pauses while the clip
  plays, the 200 ms tail, the rest at key up, the default dictionary. `silas-bench run --fast --threads 3`, one
  model at a time, under `nice -n 10 taskset -c 1,2,3` (`run.sh`). chapel1 is shared; the 1-minute load stayed
  between 0.4 and 5.3 (each row records it; the paced runs were the quiet ones), under the 8 the runner holds at.
- transcribe.cpp models run in process on its CPU backend with 3 threads; ONNX models in process through
  transcribe-rs (onnxruntime, held to 3 cores by taskset); whisper.cpp as `whisper-server` with 3 threads on the
  same cores, its CPU and peak memory added to each row (`--usage-pid`).
- English is passed to models that take a language. Nothing is warmed beyond one second of silence.
- `load_ms` in these rows counts only Silas's own engines; candidate models loaded before the clock. silas-bench now
  counts both, and the cold-load times above come from that build.

## Reproduce

See [README.md](README.md). The candidates file lists every model, file and hash; `run.sh` runs them, `summarize.py`
writes the JSON. The decoder fix builds into a separate target with `cargo --config patch.crates-io`, as the README
shows; the app's own build does not change.
